# Zazie Institute of Applied Anomalies (ZIAA) — Research Archive

Source for **https://zazieinstitute.org** — the public archive of the Zazie Institute of Applied Anomalies (ZIAA), an independent interdisciplinary research and creative‑technology initiative (experimental technology, audio research, computational creativity, speculative engineering, creative tools, prototypes, software, digital art and sound technology). Operated by Zazie Productions LLC.

The archive holds prototypes, speculative patents, research notes, anomaly post‑mortems, fellows, field stations, monographs and three interactive instruments (Acoustic Bench, Spectra Lab, VOID//OCULUS).

## Stack

- Vite 7 · React 19 · TypeScript · Tailwind CSS v4 · React Router 7
- **Static prerender**: every route is rendered to HTML at build time (`react-dom/static` + `scripts/prerender.mjs`) and hydrated on the client. No server required; every URL is a real file, so crawlers get full content, titles, canonicals and JSON‑LD without executing JavaScript.
- Self‑hosted, subsetted web fonts (STIX Two Text, latin only); no third‑party requests.

| Section | List | Record |

## SEO / quality guarantees (enforced by `npm run audit:seo`)

- Exactly one `<title>`, one meta description, one canonical (`https://zazieinstitute.org` + path) and one `<h1>` per page; titles and descriptions unique site‑wide; title budget ≈ 70 chars with record IDs preserved.
- No accidental `noindex` (only `/search` and `/404`); sitemap contains exactly the indexable pages; `robots.txt` references the sitemap.
- Every internal link resolves to a prerendered page; no trailing‑slash links; every `<img>` has `alt`.
- Semantic landmarks (`<main>`, `<nav aria-label>`, `<article>`, `<time>`), heading hierarchy, `lang="en"`.
- JSON‑LD on every page (BreadcrumbList + page‑type schema).

## Structured data & the entity graph

Every entity in the Institute has exactly one stable, absolute `@id`, allocated in `src/seo/graph.ts`.
Relationships are emitted as `{ "@id": … }` pointers rather than nested copies, so a crawler reading any
single page can resolve the whole institution:

```
Person ─memberOf(OrganizationRole)─▶ Department ─parentOrganization─▶ Division ─▶ Organization
   │                                     ▲  ▲
   ├─worksFor(EmployeeRole)─▶ Organization│  └─hasCourseInstance─▶ CourseInstance ─instructor─▶ Person
   ├─hasOccupation─▶ Occupation           │
   ├─funding─▶ MonetaryGrant ─fundedItem─▶ ResearchProject ─parentOrganization─┘
   └─knowsAbout─▶ DefinedTerm ─inDefinedTermSet─▶ DefinedTermSet

TechArticle/Report/CreativeWork ─creator─────────▶ Person
                               ─sourceOrganization▶ Department
                               ─funding──────────▶ MonetaryGrant
                               ─locationCreated──▶ Place (facility)
                               ─about────────────▶ DefinedTerm
                               ─mentions─────────▶ other records
```

Node classes in use: `ResearchOrganization`, `Organization` (divisions/departments), `ResearchProject`,
`MonetaryGrant`, `Course` + `CourseInstance`, `DefinedTermSet` + `DefinedTerm`, `Place`, `Occupation`,
`OrganizationRole`, `EmployeeRole`, `Dataset`, `DataCatalog`, `DataDownload`, `MonetaryAmount`,
`PropertyValue`, `Syllabus`, `Chapter`, `VirtualLocation`, `FundingScheme`, `Corporation`,
`LocationFeatureSpecification` — 46 distinct schema.org types across the crawl.

Two type names that often appear in SEO advice are **not** in schema.org and are deliberately not used:
`ResearchGrant` (use `MonetaryGrant`) and `FacultyAffiliation` (use `OrganizationRole`/`EmployeeRole`
as the value of `memberOf`/`worksFor`). Likewise the course type is `Course` + `hasCourseInstance`,
not `CourseOffering`. All three return 404 from schema.org and are rejected by the audit.

### Graph integrity is enforced, not assumed

`npm run audit:seo` parses every JSON‑LD block in `dist/` and fails the build when:

- a block does not parse;
- an `@type` is not a real schema.org type;
- a property is not a real schema.org property;
- an `@id` pointer is never declared anywhere in `dist/` (**dangling reference**);
- an `@id` is not absolute or not on the canonical origin.

The vocabulary is derived at runtime from the `schema-dts` devDependency
(939 types, 1509 properties), so it tracks schema.org instead of drifting from a hand‑maintained
allowlist. Record references additionally pass through `hasRecord`, matching the guard the visible UI
already applies; unresolved cross‑references in the source collections are reported by
`scripts/build-derived.mjs` rather than silently dropped.

### Honesty constraints

The Institute is non‑accredited and publishes design fiction, so the structured data deliberately
asserts **no** `educationalCredentialAwarded`, **no** `alumniOf` to real universities, **no** `sameAs`
to external identifiers, and **no** external funding body. Every grant funder is the Institute itself,
one of its internal funds, or its legal parent. Bibliographic citations are kept as plain text
(`citation`) rather than as fabricated structured publication nodes.

## Editing content

1. Edit the relevant file in `src/data/collections/`.
2. `npm run build` regenerates derived data, pages, sitemap and feed. New records get URLs automatically via `src/routes/manifest.ts`.
3. Run `npm run audit:seo` and fix any reported errors before deploying.

Brand assets (favicons, touch icons, OG image, manifest) are generated from the crest geometry by `scripts/build-brand-assets.mjs` (runs in `prebuild`).
